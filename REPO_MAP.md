## Per-node regression test

After any refactor that touches imports, Nuke plugin paths, `bria_core/` layout, or class names, run this checklist. Open the demo scene (once added under `examples/scenes/`) or a fresh Nuke session, and for each of the 11 node types:

| Step | What it validates |
|------|-------------------|
| 1. Delete and recreate from the Bria menu | `menu.py` builder still works |
| 2. Confirm expected knobs are present (prompt, mask input, project path, etc.) | Group construction + knob defs intact |
| 3. Click the Run button | Adapter → `bria_core.client` path works; User-Agent sent |
| 4. Confirm viewer refreshes after result | `sync_preview()` / internal Switch node wiring intact |
| 5. Open the Result History tab and load a prior entry | `history.py` split still wired correctly |
| 6. Save & reload the `.nk` file; confirm prompt textareas keep their intended height | `addOnScriptLoad` prompt-height fix still fires |

Run in this order (simplest to most complex):

1. **Bria RMBG** — 8 KB, single endpoint, no mask, no prompt
2. **Bria Upscale**
3. **Bria Enhance**
4. **Bria Erase** (needs mask input)
5. **Bria GenFill** (needs mask + prompt)
6. **Bria Expand**
7. **Bria FIBO Generate**
8. **Bria FIBO Edit**
9. **Bria FIBO Edit Recipes** — verifies 99 preset catalog and object/comp targeting UI
10. **Bria Generate VGL** (Structured Prompt)
11. **Bria Sequence Output** — verifies upstream DAG walking; set a small frame range (e.g. 1-3) with an RMBG upstream; confirm per-frame PNGs write to the output path

Finally, validate cross-DCC config fallback: place only `houdini_api_key` in `~/.bria/bria.json` and run any Nuke node — it should succeed via the cross-DCC fallback.
